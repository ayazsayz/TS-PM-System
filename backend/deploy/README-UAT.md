# Deploying Cadence to MonsterASP.NET (UAT)

This deploys the **whole app as one site**: the .NET 10 API serves the built React SPA from
`wwwroot/` and its own API under `/api/*`, backed by one MonsterASP MSSQL database. Same origin,
so there is no CORS to configure, and it fits the free plan's 1-site / 1-database limit.

```
Browser ──HTTPS──▶ MonsterASP site (ASP.NET Core, net10.0)
                    ├─ /            → wwwroot/index.html   (React SPA)
                    ├─ /assets/*    → static files
                    └─ /api/*       → API  ──▶  MonsterASP MSSQL 2025
```

MonsterASP supports .NET 10 and MSSQL 2025 natively, so this is a normal **framework-dependent**
publish — no self-contained runtime bundle needed.

---

## Prerequisites

- A MonsterASP.NET hosting account with **one website** and **one MSSQL database** created.
- Local tooling: **.NET 10 SDK**, **Node 20+**, and either Visual Studio (for WebDeploy) or an
  FTP client.

---

## A. Create the database (control panel)

1. In the MonsterASP control panel, create an **MSSQL database**.
2. Copy the connection details it shows — server host (e.g. `dbXXXX.public.databaseasp.net`),
   database name, user, and password. You'll need these in step D. The connection string looks
   like:

   ```
   Server=dbXXXX.public.databaseasp.net; Database=dbXXXX; User Id=dbXXXX; Password=YOUR_PASSWORD; TrustServerCertificate=True; Encrypt=False;
   ```

> The schema is created automatically — the app runs EF Core migrations on first startup
> (`MigrateAsync`). You do **not** need to run migrations by hand. (A manual fallback is at the
> bottom of this file.)

---

## B. Build the deploy package (local)

From the repo:

```powershell
./backend/deploy/build-uat.ps1
```

This builds the SPA in production mode (relative `/api` calls), copies it into
`backend/src/Tspm.Api/wwwroot/`, and publishes the API to `backend/deploy/publish/`. That
`publish/` folder is what you upload.

---

## C. Upload the files

**Option 1 — WebDeploy (recommended):**
1. In the control panel, **activate the WebDeploy account** and download the publish profile
   (`.publishSettings`).
2. In Visual Studio: right-click **Tspm.Api → Publish → Import Profile**, pick the
   `.publishSettings`, and publish. (Or import it into the `dotnet` MSDeploy flow.)

**Option 2 — FTP:** upload the **contents** of `backend/deploy/publish/` into your site's root
(the folder IIS serves — usually `wwwroot` or `httpdocs`). Include `web.config` (generated by
`dotnet publish`); it wires up the ASP.NET Core Module.

---

## D. Set the secrets on the server

The committed `appsettings.Production.json` ships with **blank** secrets on purpose. Fill them on
the server — edit `appsettings.Production.json` through the control-panel **File Manager** (or set
them as app settings). MonsterASP runs the app in the **Production** environment by default, so
this file is the one that's read.

```jsonc
{
  "ConnectionStrings": {
    "DefaultConnection": "Server=dbXXXX.public.databaseasp.net; Database=dbXXXX; User Id=dbXXXX; Password=YOUR_PASSWORD; TrustServerCertificate=True; Encrypt=False;"
  },
  "Jwt": {
    "SigningKey": "PASTE_A_LONG_RANDOM_SECRET"   // >= 32 bytes
  },
  "Seed": {
    "AdminEmail": "you@yourcompany.com",
    "AdminPassword": "A-Strong-Passw0rd!"        // change from the dev default
  }
}
```

Generate a strong signing key locally:

```powershell
[Convert]::ToBase64String((1..48 | ForEach-Object { Get-Random -Max 256 }))
```

> **Security:** never commit real secrets. The dev default admin (`admin@etech.io / Passw0rd!`)
> must **not** be used on a reachable site — override the seed admin above, and change the password
> on first login. The JWT key must be long and random, or tokens can be forged.

---

## E. First boot & smoke test

1. Browse to your site URL. On first request the app migrates the DB and seeds the admin (watch
   the MonsterASP application log if you enabled stdout logging).
2. The SPA should load; deep links like `/attendance` should resolve (SPA fallback).
3. Log in as the seeded admin, then **change the password**.
4. `/swagger` is intentionally off in Production.

---

## F. HTTPS

Enable the free **Let's Encrypt** certificate for the site in the control panel and force HTTPS.
Tokens are bearer JWTs, so HTTPS is required, not optional.

---

## Manual migration (fallback only)

If you'd rather apply the schema before first boot, generate an idempotent script locally and run
it once in SSMS against the MonsterASP DB:

```powershell
dotnet ef migrations script --idempotent `
  --project backend/src/Tspm.Infrastructure `
  --startup-project backend/src/Tspm.Api `
  -o backend/deploy/migrate.sql
```

Then set `Seed:Enabled` as desired (leave `true` to still seed the admin/roles; the migration step
inside seeding is a no-op once the schema already exists).

---

## Updating a deployed site

Re-run `build-uat.ps1` and re-upload `publish/`. New migrations apply automatically on the next
start. Secrets on the server are preserved as long as you don't overwrite `appsettings.Production.json`
(FTP: skip that file; WebDeploy: it isn't in source with secrets, so it won't clobber yours).
